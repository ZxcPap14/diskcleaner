# План разработки DiskCleaner Pro

Обновлён: 27.10.2026 · текущая версия 4.17.0

Порядок — по отношению «польза / риск / время». Каждый пункт считается
сделанным только после тестов, `ruff`, `mypy` и проверки на живом рендере
(1180×760 и 1024×660, light/dark).

Принципы, которые не меняются от релиза к релизу:

- по умолчанию ничего не выбрано, необратимое — только после подтверждения;
- «освобождено» подтверждается замером, а не обещанием;
- слой E ничего не удаляет — только показывает и объясняет;
- не добавляем операции, которые нельзя отменить или объяснить.

## 4.14.0 — «SMART полнее» ✅ сделано (27.10.2026)

Задача: закрыть разрыв с CrystalDiskInfo там, где это честно возможно.
Диагностика на живой машине: оба диска SATA (NVMe нет), `Get-PhysicalDisk`
без admin пуст (smphost), ATA-WMI требует прав администратора — значит,
главная ценность не «ещё атрибуты», а полная таблица + пороги + честные
показатели для NVMe-машин.

- [x] **Полная таблица ATA-атрибутов** — все переданные диском атрибуты
      (не только пять), отсортированы по ID, стандартные имена для ~70
      известных ID, формат «value/worst · порог · raw». Температурные
      атрибуты (194/190/231) и наработка (9) — в человеческом виде.
- [x] **Пороги** — `MSStorageDriver_FailurePredictThresholds` читается тем

      «—», без догадок.
- [x] **Показатели для NVMe и машин без admin** — когда ATA-данных нет,
      но есть StorageReliabilityCounter (температура/наработка/износ/

- [x] **Сводный статус** — `health_badge()`: «плохое» только из
      HealthStatus системы, «внимание» из ненулевых критических
      атрибутов (05/187/196/197/198), WARN или 65 °C+; иначе «хорошее»
      при наличии данных, честное «нет данных» без них.
- [x] **UI** — в деталях диска: строка сводного статуса, полная таблица
      SMART с выравниванием, пометка источника данных и понятная

      Компактная строка-саммари ключевых атрибутов сохранена.
- [x] 5 новых тестов + обновлены существующие под полную таблицу

## 4.15.0 — «История занятости диска» ✅ сделано (27.10.2026)

Задача из бэклога 4.10.0: снапшоты занятости, график тренда и прогноз
«место кончится к дате X». Уникальная функция — нет ни у CCleaner, ни у
CrystalDiskInfo, ни у WizTree.

- [x] **Снапшоты** — таблица `disk_snapshots` в той же SQLite (схема v4),
      пишутся при запуске дашборда и после каждой операции очистки
      (`add_operation` → снапшот), но не чаще раза в 6 часов: важен
      тренд, а не частота. Сбой снапшота не ломает запись истории.
- [x] **Прогноз с честными условиями** — `forecast_free()`: линейная
      регрессия по точкам; показывается только при ≥ 4 точках за ≥ 7
      дней; при растущем/плоском месте — «прогноз не требуется»
      (отличается от «недостаточно данных» через `insufficient_data()`);
      при пологом тренде (>10 лет) дата не выдаётся; порог — 5 % тома.
      Подпись всегда раскрывает основание: скорость и число точек.
- [x] **График в дашборде** — новый `UsageTrendChart` (Canvas в стиле
      графика истории): линия свободного места, заливка, подписи дат,
      крайние значения; перерисовка при смене диска и темы.
- [x] 10 новых тестов: интервал снапшотов, порядок серии, минимальные
      условия прогноза, точность наклона (−1 ГБ/день → ~73 дня),
      отказ при росте места, миграция базы v3→v4, снапшот при
      add_operation. ruff/mypy зелёные, pytest — 450 тестов; smoke
      дашборда с растущим и падающим трендом.

Итог: `services/disk_usage.py`, таблица `disk_snapshots` в
`models/history.py`, `ui/components/usage_chart.py`, карточка тренда
в `ui/views/dashboard.py`.
