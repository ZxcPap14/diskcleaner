## 0. Резюме для решения

### Что уже есть

DiskCleaner Pro 4.6.0 — это **зрелый очиститель с элементами диагностики**, а не «универсальный комбайн»:

- 51 рабочий Python-модуль, около 8 000 строк (без легаси);
- 9 экранов: главная, очистка, анализ, диски, дубликаты, история, автозагрузка, деинсталлятор, настройки;
- модульные очистители: система, браузеры, dev tools, приложения, AI/ML, auto-discover, пользовательские правила;
- безопасное удаление: `IFileOperation` → fallback `SHFileOperationW`, корзина, `PathGuard`, уровни 🟢/🟡/🔴;
- история в SQLite с WAL, фильтры, экспорт JSON/CSV, логи с ротацией, UAC по кнопке;
- SMART-сводка, read-only проверка поверхности, treemap, поиск дубликатов, управление автозагрузкой, деинсталлятор с остатками;
- 160 тестов, ruff/mypy, CI, exe + установщик + portable ZIP.

### Чего не хватает для «универсального»

1. **Очистка не привязана к выбранному диску.** Анализатор умеет `D:\`, а очистители — нет. Хуже: `CleanEngine` измеряет свободное место **системного диска**, поэтому для `D:` отчёт «освобождено» может быть ложным.
2. **Нет быстрого анализа.** Только рекурсивный `os.scandir`; полный обход 1 ТБ на HDD — десятки минут, на миллионах файлов UI деградирует.
3. **SMART только верхнеуровневый.** Нет полной таблицы атрибутов, NVMe-логов, истории, графиков, оповещений.
4. **Нет бенчмарка, управления разделами, TRIM/дефрагментации, безопасного стирания, backup/clone, планировщика, tray, CLI.**
5. **Нет настоящего низкоуровневого слоя.** PowerShell/WMI — хорошо для старта, но недостаточно для MFT, SMART-атрибутов, разделов, VSS и безопасного стирания.
6. **Поставка без подписи и автообновления.** SmartScreen, отсутствие onedir, нет канала обновлений.
7. **Техдолг безопасности:** Telegram `tdata`, kill `explorer.exe`, `shell=True` в деинсталляторе, поштучная корзина через PowerShell.

### Предлагаемая стратегия

Не пытаться в лоб повторить DiskGenius + CrystalDiskInfo + CCleaner + Macrium в одном релизе. Это 1–2 года разработки. Вместо этого —

> **«Один безопасный кокпит для 80% рутинных задач с дисками»: очистка → анализ → диагностика → обслуживание → управление → защита данных.**

Три режима:

- **Basic** — безопасная очистка и анализ, ничего не ломает;
- **Expert** — SMART-детали, бенчмарк, разделы, стирание, backup;
- **Danger** — необратимые операции только с вводом серийного номера диска, резервной копией таблицы разделов и таймером.

### 2.2. Выводы

1. **Ни один конкурент не покрывает всё хорошо.** DiskGenius ближе всех к «всё-в-одном», но сложен и рискован. CCleaner силён в очистке, WizTree — в анализе, CrystalDiskInfo — в диагностике, Macrium — в backup.
2. **Свободная ниша:** безопасный, прозрачный, русскоязычный, без рекламы, объединяющий очистку + анализ + здоровье + базовое обслуживание. Не нужно сразу лезть в recovery и RAID.
3. **Главный дифференциатор — доверие:** понятный план операции, реальные цифры, обратимость, никаких «ускорений» и реестрового мусора.
4. **«Универсальность» = единый кокпит, а не замена всем узким специалистам.** Для сложного восстановления данных и RAID лучше честно рекомендовать специализированный инструмент.

## 4. Позиционирование и границы продукта

### 4.1. Три круга

```
┌─────────────────────────────────────────────────────────────┐
│  1. Безопасная очистка                                      │
│     мусор, кэши, дубликаты, большие файлы, по диску         │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  2. Анализ и диагностика                              │  │
│  │     MFT-скан, treemap, SMART, поверхность, бенчмарк   │  │
│  │                                                       │  │
│  │  ┌─────────────────────────────────────────────────┐  │  │
│  │  │  3. Управление и защита                         │  │  │
│  │  │     разделы, TRIM, wipe, backup, clone          │  │  │
│  │  └─────────────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

- **Круг 1** — то, что можно безопасно дать любому пользователю. Это ядро продукта.
- **Круг 2** — Expert-режим; требует прав администратора, но не меняет данные (кроме бенчмарка, который пишет временный файл).
- **Круг 3** — Danger-режим; необратимые операции. Только с резервной копией, подтверждением и журналом.

### 4.2. Что сознательно не делаем

- Реестровый «cleaner» и «оптимизатор» — низкая польза, высокий риск.
- «Ускорение интернета», RAM-cleaner, «1 клик до скорости света».
- Write/erase-тесты поверхности по умолчанию.
- Дефрагментацию SSD.

## 5. Целевая архитектура

### 5.1. Принципы

1. **Безопасность важнее функций.** Любая необратимая операция проходит через план, подтверждение и журнал.
2. **Один источник правды о дисках.** `PhysicalDisk → Partition → Volume → MountPoint`.
3. **UI не знает низкоуровневых деталей.** Всё через сервисы и job-модель.
4. **Никаких Tk из воркеров.** Только `UiDispatcher`/очередь.
5. **Декларативные цели очистки.** Пути, режимы, риски — в спецификациях, а не в классах-клонах.
6. **Права — по операции.** Приложение стартует без UAC; helper повышает права только для конкретной задачи.
7. **Всё измеримо.** До/после, объём, скорость, ошибки, длительность.

### 5.3. Низкоуровневый helper

**Зачем:** Python + PowerShell не подходят для MFT, полного SMART, разделов, VSS и безопасного стирания.

**Рекомендация:** отдельный `dc_helper.exe` на **C# (.NET 8, self-contained, trimmed)**.

Почему C#:

- нативные Windows API, COM (VSS/VDS), IOCTL, `System.Management`;
- проще поддерживать, чем C++/Rust, для Windows-only;
- self-contained сборка ~15–30 МБ, можно подписать;
- JSON-RPC по named pipe/stdin-stdout, без сетевых портов.

Альтернатива — Rust (меньше размер, нет рантайма), но COM/VSS и разработка сложнее. Решение зафиксировать до этапа 8.

**Команды helper (по этапам):**

| Команда | Этап | Назначение |
|---|---|---|
| `disk.list` | 7 | физические диски, тома, разделы, bus, размер |
| `smart.read` | 9 | ATA/NVMe атрибуты, пороги, температура, износ |
| `smart.selftest` | 9 | короткий/длинный self-test |
| `mft.scan` | 8 | MFT/USN-обход NTFS |
| `bench.run` | 9 | SEQ/RND read/write, IOPS, latency |
| `partition.list` | 11 | разделы,offset,type,volume |
| `partition.edit` | 11 | create/delete/format/resize (опасно) |
| `wipe.run` | 10 | free space / disk / secure erase |
| `vss.snapshot` | 12 | теневые копии |
| `clone.run` | 12 | клонирование тома |

**До появления helper:** использовать PowerShell-командлеты (`Get-Disk`, `Get-Partition`, `Get-Volume`, `Optimize-Volume`, `chkdsk`, `wbadmin`) как временный слой, но не строить на них необратимые операции.

### 5.4. Job-модель и события

```
UI → JobManager.submit(JobSpec) → worker/native helper
   ← progress/cancel/result через очередь
   ← UiDispatcher.after(50) обновляет UI
```

- `JobSpec`: тип, параметры, отмена, приоритет.
- `Job`: id, статус, прогресс, скорость, ETA, результат, ошибки.
- События: `scan.*`, `clean.*`, `smart.*`, `partition.*`, `backup.*`.
- Один job на диск/операцию; глобальный лимит параллельности.
- Все результаты — в `OperationResult` и журнал.

### 5.5. Модель данных

```text
PhysicalDisk(id, model, serial, bus, size, firmware, smart_json)
Partition(id, disk_id, number, offset, size, type, guid, volume_id)
Volume(id, mount, label, fs, size, free, bitlocker, disk_id)
CleanTarget(id, group, risk, paths, actions, admin, volume_scope)
Operation(id, ts, type, targets, bytes_planned, bytes_freed, status, details_json)
SmartSample(disk_id, ts, temperature, wear, hours, attributes_json)
BenchmarkRun(id, disk_id, volume, profile, read_mbps, write_mbps, iops, latency_json)
ScanSnapshot(id, root, volume, created_at, nodes_db)
```

- SQLite: история операций, SMART-история, бенчмарки, кэш сканов.
- JSON: настройки, правила, профили планировщика.
- Все записи — атомарно, с миграциями схемы.

### 5.6. Модель безопасности

```
TargetSpec → PathGuard/VolumeGuard → OperationPlan (dry-run)
           → подтверждение по RiskLevel → выполнение → верификация
           → журнал + отчёт
```

| Уровень | Примеры | Подтверждение |
|---|---|---|
| 🟢 GREEN | temp, кэши, корзина | без диалога, preview доступен |
| 🟡 YELLOW | данные приложений, автозагрузка | диалог с объёмом |
| 🔴 RED | системные файлы, разделы, формат | ввод «УДАЛИТЬ» + backup |
| ⚫ BLACK | secure erase, wipe диска | серийный номер + 10-сек таймер |

Дополнительно:

- `PathGuard`: запрет корней, `C:\Windows`, `Program Files`, `ProgramData`, домашних папок, reparse points.
- `VolumeGuard`: нельзя удалять/форматировать/system-resize том, на котором стоит Windows.
- `PartitionTableBackup`: сохранить MBR/GPT sectors перед изменением; кнопка «Восстановить таблицу».
- `AuditLog`: append-only JSONL + SQLite, кто/что/когда/сколько/результат.
- Никаких «тихих» удалений: всё через `OperationPlan`.

### 5.7. Производительность

| Задача | Сейчас | Цель |
|---|---|---|
| Полный анализ NTFS | рекурсивный `scandir` | MFT/USN + fallback, < 60 с на 1 млн файлов |
| Повторный анализ | кэш анализатора | инкрементально по USN |
| Дерево файлов | Tk-дерево | виртуализированный список, миллионы строк |
| Treemap | пересчёт | кэш + resize без пересчёта |
| SMART | PowerShell каждый раз | helper + кэш + фон |
| Проверка поверхности | последовательная | без изменений, но с картой/паузой |
| Очистка | поштучная корзина | пакетный `IFileOperation` для всех файлов |

### 5.8. Поставка и обновление

- Перейти с `onefile` на `onedir` + установщик: быстрый старт, меньше ложных срабатываний антивируса.
- Portable ZIP: данные рядом с exe (`data/`), не в `%APPDATA%`.
- Подпись кода (EV/OV) — обязательна для распространения; иначе SmartScreen.
- Автообновление: подписанный manifest + SHA-256, отключаемое.
- Каналы stable/beta; откат на предыдущую версию.
- CI: сборка, тесты, подпись, публикация артефактов и хэшей.

| Потеря данных при очистке | Средняя | Критическое | PathGuard, preview, корзина, подтверждения, аудит |
| Потеря данных при разделах | Средняя | Критическое | Backup таблицы, system disk block, VM-тесты, dry-run |
| Ложные отчёты «освобождено» | Высокая | Высокое | Замер по целевому тому, верификация, тесты |
| Антивирус/SmartScreen блокирует | Высокая | Высокое | onedir, подпись, меньше «тихих» операций |
| MFT-парсер ошибается | Средняя | Высокое | Fallback на scandir, контрольные суммы, тесты |
| SMART не читается через USB/RAID | Высокая | Среднее | Честно показывать «недоступно», рекомендовать smartctl |
| Бенчмарк нагружает систему | Средняя | Среднее | Предупреждение, выбор тома, малый размер по умолчанию |
| Разрастание scope | Высокая | Высокое | Этапы, DoD, «Won't»-список |
| Нет аппаратного тестирования | Высокая | Высокое | VM + парк из SATA/NVMe/USB, ручной чек-лист |
| GPL-лицензии при bundling | Средняя | Среднее | Не встраивать smartctl/nvme-cli без compliance; свой helper |
| Нет подписи → недоверие | Высокая | Высокое | Бюджет на сертификат, SHA-256, прозрачные релизы |

## 9. Тестирование и качество

### 9.1. Уровни

- **Unit:** `PathSpec`, volume resolution, plan, risk, SMART-парсер, benchmark-математика, partition-парсер, backup manifest.
- **Integration:** временные каталоги, фейковые диски, SQLite-миграции, job-модель.
- **VM:** Hyper-V/VirtualBox с виртуальными дисками для разделов, форматирования, wipe, clone.
- **Hardware:** SATA HDD/SSD, NVMe, USB-flash, exFAT, BitLocker, RAID.
- **Fault injection:** access denied, диск отключён, sleep, длинные/Unicode-пути, занятые файлы.
- **UI smoke:** запуск, переключение всех вьюх, отмена, закрытие.
- **Performance:** 1 млн файлов, 1 ТБ, поверхность 512 МБ/4 ГБ.

### 9.2. CI

- Windows runner: ruff, mypy, pytest, compileall;
- сборка onedir/installer;
- smoke install/uninstall;
- публикация артефактов и SHA-256;
- ночные тесты на VM (опционально).

- [ ] P0 закрыты, есть регрессионные тесты.

- [ ] «Освобождено» совпадает с изменением свободного места (±5%).
- [ ] Отмена работает во всех длинных операциях.
- [ ] Установка/удаление/обновление на чистой Windows 10/11.
- [ ] Нет рекламы, телеметрии по умолчанию, скрытых действий.
- [ ] README/CHANGELOG/лицензии обновлены.
- [ ] Артефакты подписаны (когда появится сертификат) и имеют SHA-256.

## 11. Открытые вопросы к владельцу

1. **Scope:** идём по плану «очистка → анализ → диагностика → автопилот → разделы → backup» или сразу целимся в разделы/backup?
2. **Helper:** C# (.NET 8 self-contained) или Rust? C# быстрее в разработке, Rust компактнее.
3. **Подпись:** есть ли возможность купить OV/EV-сертификат? Без него SmartScreen будет мешать распространению.
4. **Backup/clone:** делаем сами или интегрируем существующий движок (wbadmin/Clonezilla/Macrium)?
5. **Автообновление и телеметрия:** нужен ли канал обновлений и opt-in краш-репорты?
6. **Приоритет:** разделы или backup/clone после v5.0?
7. **Легаси:** удалить `core.py`, `gui.py`, `cleaners.py`, `scanners.py`, `analyzer.py` после стабилизации или оставить как архив?
8. **Git:** инициализировать репозиторий и вести историю изменений?

## Приложение A. Что можно сделать уже сейчас без helper

- Очистка по диску и честный free-space accounting.
- План операции и preview.
- CLI.
- Планировщик через `schtasks`.
- Инвентаризация разделов через `Get-Disk`/`Get-Partition`/`Get-Volume`.
- TRIM/defrag/chkdsk через `Optimize-Volume`/`defrag`/`chkdsk`.
- Wipe free space (файловый, не raw).
- SMART-сводка и история (PowerShell).
- Бенчмарк на файлах (Python + `FILE_FLAG_NO_BUFFERING`).

Этого достаточно для v4.7–v5.0. Helper нужен для MFT, полного SMART, разделов и backup.
