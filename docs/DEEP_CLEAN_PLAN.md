# DiskCleaner Pro — план глубокой очистки

**Статус:** на согласование  
**Версия проекта:** 4.6.0  
**Дата:** 24.10.2026  
**Область:** `cleaners/`, `services/`, `models/`, `ui/`  
**Легаси-модули** (`core`, `gui`, `scanners`, `analyzer` в корне пакета) не изменяются и остаются исключёнными из сборки.

---

## 0. Кратко: что предлагается и зачем

Сейчас приложение умеет очищать кэши, но делает это узко и не всегда честно:

- считает освобождённое место только на системном диске;
- берёт «план» из размера, который был получен прошлым сканом;
- не проверяет, что две цели не удаляют одни и те же файлы;
- чистит браузеры только в профиле `Default`;
- удаляет установленные расширения и AI-модели под видом «кэша»;
- убивает `explorer.exe`, чтобы почистить эскизы;
- запускает системные операции без проверки прав и не проверяет результат;
- не показывает план удаления до нажатия «Очистить».

Предлагается не «добавить ещё десять кнопок», а сделать **глубокую очистку как отдельный слой продукта**:

1. **Шире по безопасным кэшам.** Все профили Chromium-браузеров, кэши шейдеров GPU, дампы, отчёты WER, кэш обновлений, кэш доставки, кэш эскизов без убийства проводника, кэши приложений по проверенным путям.
2. **Глубже по системе.** Компонентное хранилище WinSxS через `DISM`, `Windows.old`, файл гибернации, старые точки восстановления, логи CBS — только через поддерживаемые Windows механизмы и только с явным подтверждением.
3. **Аккуратнее с компонентами.** AI-модели, расширения VS Code/Antigravity, браузерные AI-модели и toolchain-кэши перестают быть «кэшем». Для них — отдельный слой с ценой восстановления и явным выбором.
4. **Честнее по цифрам.** План до удаления, замер по каждому затронутому тому, отдельный учёт корзины, двойная метрика «удалено файлов / изменилось свободное место».
5. **Безопаснее.** Единые защищённые пути для всех очистителей, запрет обхода junction/symlink, возрастной фильтр, отказ от принудительного закрытия приложений, восстановление служб в `finally`.
6. **Понятнее.** У каждой цели есть «почему это можно удалить» и «что будет, если удалить». По умолчанию не выбрано ничего.

**Ожидаемый эффект:** на машине разработчика аудит нашёл **≈ 18 ГБ** потенциальной очистки, из которых текущая версия видит и умеет около **5 ГБ**, а безопасный набор нового движка — **≈ 7 ГБ** вместе с корзиной (≈ 4 ГБ без неё). Это не обещание для всех машин, а замер конкретного профиля (см. §2.3).

**Сроки (один разработчик):**

| Этап | Содержание | Оценка |
|---|---|---|
| 1 | Честный фундамент: план, учёт по томам, пересечения, защита, исправление опасных целей | 5–7 дней |
| 2 | Безопасный охват: новые кэши, все профили, GPU-кэши, корзина по томам, UI плана | 7–10 дней |
| 3 | Системный слой: DISM, `Windows.old`, гибернация, точки восстановления, elevation | 10–14 дней |
| 4 | Компоненты и остатки: модели, расширения, dev-кэши, orphan-папки, Docker/WSL | 10–14 дней |

## 1. Цели и не-цели

### 1.1. Цели

1. Освобождать **больше места**, не повышая риск потери пользовательских данных.
2. Сделать результат **проверяемым**: пользователь видит, что именно будет удалено, сколько и почему.
3. Сделать учёт **честным**: «освобождено» = изменение свободного места на затронутых томах, а не сумма предполагаемых размеров.
4. Исключить **опасные и бессмысленные** операции из безопасного набора.
5. Дать **восстановимость** там, где она возможна: корзина для пользовательских данных, команда повторной установки для моделей/расширений, обратная команда для гибернации.
6. Сохранить архитектуру проекта: `models` → `services` → `cleaners` → `ui`, без Tk из воркеров.

### 1.2. Не-цели

- Чистка реестра, «твики» производительности, отключение служб «для скорости».
- Дефрагментация, TRIM, проверка поверхности — это другие разделы продукта.
- Автоматическое удаление `Documents`, `Downloads`, `Desktop`, фото, видео и любых пользовательских документов.
- Ручное удаление файлов внутри `C:\Windows\WinSxS`, `C:\Windows\Installer`, `C:\ProgramData\Package Cache` — это ломает обслуживание и удаление программ.
- Изменение `pagefile.sys` и отключение файла подкачки.
- Тихое удаление установленных моделей, расширений и программ.
- «Оптимизация» через принудительное завершение процессов.

## 2. Аудит текущей очистки

### 2.1. Что уже работает хорошо

- `BaseCleaner` с `get_size()` / `clean()`, уровни `SAFE / CAUTION / ADVANCED`.
- Параллельный скан с отменой (`ScanEngine`, 4 потока).
- `safe_rmtree` / `safe_rm_contents` не идут внутрь junction и symlink.
- Пакетное удаление `IFileOperation` с fallback на `SHFileOperationW` (`services/batch_delete.py`).
- Корзина как опция (`CleanOptions.to_recycle`).
- Защита пользовательских правил (`services/safety.py`), хотя встроенные очистители её не используют.
- История операций, отчёты, логи, UAC-кнопка, MD3-UI.

Это хороший фундамент. Проблема не в отсутствии механизмов, а в том, что глубокий сценарий их **не использует последовательно**.

### 2.2. Найденные дефекты

| ID | Дефект | Последствие | Этап |

## 3. Целевая архитектура

### 3.1. Слои и политика риска

| Слой | Название | Примеры | Пресет Easy | Права | Обратимость |
|---|---|---|---|---|---|
| A | Безопасные кэши | браузеры, Temp, WER, дампы, GPU-кэши, эскизы | да, с возрастом | пользователь | файлы пересоздаются |
| B | Системное обслуживание | WinSxS, WU, DO, `Windows.old`, гибернация, restore points | нет | администратор | частично/необратимо |
| C | Компоненты и модели | AI-модели, расширения, toolchain-кэши, Docker/WSL | нет | пользователь/админ | повторная загрузка/установка |
| D | Остатки и пользовательские данные | orphan-AppData, старые логи, пустые папки | нет | пользователь | корзина |
| E | Крупные системные файлы | `pagefile.sys`, `hiberfil.sys`, `WinSxS`, `Installer` | только показ | — | управляется ОС |

Правило: **Easy = только A, только цели с `min_age_hours > 0`, только не занятые процессами, ничего не выбрано по умолчанию.** Кнопка «Безопасный набор» отмечает A, но не запускает удаление.

### 3.2. `TargetSpec` — описание цели

Новый модуль `models/target.py`:

```python
@dataclass(frozen=True)
class TargetSpec:
    id: str
    name: str
    group: str
    layer: str                  # "A" | "B" | "C" | "D" | "E"
    safety: str                 # SafetyLevel
    kind: str                   # "dir_contents" | "dir_remove" | "files"
                                # "glob" | "command" | "api"
    roots: tuple[Path, ...] = ()
    patterns: tuple[str, ...] = ()
    min_age_hours: int = 0
    admin: bool = False
    recycle: bool = True
    close_apps: tuple[str, ...] = ()
    why: str = ""               # «почему это можно удалить»
    loss: str = ""              # «что будет, если удалить»
    restore_hint: str = ""      # как вернуть
    verify: str = ""            # как проверить результат
```

Требования:

- `roots` — только абсолютные пути, нормализованные один раз.
- `patterns` — только внутри `roots`; никаких `**` от корня диска.
- `kind="command"` допускает только зарегистрированные команды из белого списка, без `shell=True`.
- `kind="api"` — DISM, `SHEmptyRecycleBinW`, `powercfg`, VSS; команда и аргументы заданы кодом, не пользователем.
- `why` и `loss` обязательны: UI не показывает цель без объяснения.

### 3.3. `Planner` и `OperationPlan`

Новый модуль `services/planner.py`:

```python
@dataclass
class PlannedAction:
    target_id: str
    path: Path | None
    bytes: int
    volume: str
    action: str                 # "delete" | "recycle" | "command"
    mtime: float
    reason: str

@dataclass
class OperationPlan:
    id: str
    actions: list[PlannedAction]
    totals_by_volume: dict[str, int]
    totals_by_layer: dict[str, int]
    warnings: list[str]
    requires_admin: bool
    skipped: list[dict]         # путь + причина
    created_at: float
```

Планировщик обязан:

1. Развернуть цели в конкретные файлы/папки или команды.
2. Нормализовать пути: `abspath` + `normcase`, длинные пути — `\\?\`.
3. **Удалить пересечения**: если выбран родитель, дочерние действия отбрасываются; если два правила указывают на один файл — остаётся одно.
4. Отбросить защищённые пути и пути вне `roots`.
5. Отбросить файлы моложе `min_age_hours`.
6. Отбросить reparse point’ы, symlink’и, cloud placeholders.
7. Определить том для каждого действия; посчитать байты по томам.
8. Проверить права: `admin`-цели помечаются, но не выполняются без прав.
9. Сформировать предупреждения: приложение запущено, служба будет остановлена, удаление необратимо, потребуется повторная загрузка.
10. Ограничить объём: не более N файлов на цель (например, 200 000); если больше — работать на уровне папок и честно писать «оценка».

`OperationPlan` сериализуется в JSON. Это нужно для двух сценариев:

- показать пользователю до удаления;
- перезапустить приложение с правами администратора и **продолжить тот же план**, не теряя выбор.

### 3.4. Честный учёт

`CleanEngine` переписывается вокруг плана:

| Показатель | Как считается |
|---|---|
| `planned` | сумма `bytes` действий плана на момент планирования |
| `removed` | сумма размеров файлов, которых **проверенно** больше нет |
| `volume_delta` | `free_after - free_before` по каждому затронутому тому |
| `freed` | `max(0, volume_delta)`; для команды — единственная метрика |
| `recycled` | сумма размеров файлов, перемещённых в корзину; **не входит в `freed`** |
| `remaining` | повторное сканирование цели после очистки |
| `confidence` | `high`, если `removed` и `volume_delta` расходятся < 10 %; иначе `estimate` |

Правила:

- Если цель затрагивает два тома, дельта считается по каждому и суммируется.
- Если очистка была в корзину, `freed = 0`, `recycled > 0`, в отчёте отдельная строка.
- Другие процессы могут менять свободное место; поэтому храним обе метрики и показываем расхождение, а не подгоняем одну под другую.
- Для hardlink/разрежённых файлов (WinSxS, Docker) логическая сумма не используется как «освобождено»; только дельта тома или отчёт API.
- `planned` больше не читается из `cleaner.size`: план — источник истины.
- После очистки `cleaner.size = remaining`, а не `0`.

### 3.5. Исполнение

1. План перепроверяется непосредственно перед удалением: путь всё ещё внутри `roots`, не защищён, возраст всё ещё подходит.
2. Удаление — пакетно через `delete_many` (IFileOperation), по тому и по политике корзины.
3. Папки, у которых нужно сохранить саму папку, чистятся режимом «содержимое», а не `rmtree`.
4. Занятые файлы: одна повторная попытка, затем `locked` в отчёт. Процессы не убиваются.
5. Службы: `try/finally`, восстановление предыдущего состояния; если остановить не удалось — цель прерывается с понятной ошибкой.
6. Отмена — между чанками (например, по 500 путей), чтобы реакция была < 1 с.
7. Прогресс — по целям и байтам, только через `UiDispatcher`.
8. Журнал — JSONL: `plan_id`, цель, путь, действие, результат, код ошибки, байты. Содержимое файлов не пишется. Хранение 30 дней.

Классификация ошибок: `not_found`, `locked`, `access_denied`, `readonly`, `in_use`, `reparse`, `path_too_long`, `cloud_placeholder`, `service_failed`, `unknown`. В UI — топ-3 причины на цель, а не одна строка «Ошибка».

### 3.6. Инварианты безопасности

1. Никогда не удалять путь вне объявленных `roots`.
2. Никогда не удалять сам корень, если это не `dir_remove` с явным подтверждением.
3. Никогда не идти внутрь junction/symlink/reparse point.
4. Никогда не удалять защищённые корни: корень диска, `Windows`, `Program Files`, `ProgramData`, профиль пользователя, личные папки.
5. Никогда не удалять cloud placeholders и offline-файлы.
6. Никогда не удалять `pagefile.sys`, `swapfile.sys`, `hiberfil.sys` как файлы — только поддерживаемой командой.
7. Никогда не оставлять службу остановленной.
8. Никогда не удалять пользовательские документы автоматически; только корзина и только после явного выбора.
9. Никогда не считать корзину освобождённым местом.
10. Никогда не выполнять системные цели без администратора.
11. Никогда не удалять установленные расширения и модели в безопасном наборе.
12. Никогда не убивать Explorer/браузер/Telegram ради удаления файлов.
13. Никаких wildcard за пределами `roots`.
14. План перепроверяется перед исполнением; устаревший план не выполняется вслепую.

### 3.7. Права администратора

- Планирование доступно без прав: размеры и список файлов читаются, системные цели помечаются замком.
- Если выбран слой B, UI предлагает «Перезапустить с правами и продолжить план».
- План сохраняется в `%TEMP%\diskcleaner\plan-<id>.json`, приложение перезапускается через существующий `services/elevation.py` с аргументом `--apply-plan`.
- После elevated-запуска план проверяется заново (пути и возраст), показывается финальное подтверждение, затем очистка.
- Если пользователь отказался от UAC — план остаётся, системные цели помечаются «пропущено: нет прав», безопасные цели можно выполнить без перезапуска.

Обозначения: **A** — безопасные кэши, **B** — системное обслуживание, **C** — компоненты/модели, **D** — остатки, **E** — только показ.  
Пресет: `Easy` — входит в безопасный набор; `Review` — только после просмотра; `Off` — не предлагается по умолчанию.

Цели, помеченные `(admin)`, входят в безопасный набор, но выполняются только после повышения прав; без прав они пропускаются с понятным статусом, а не с «OK».

**Почему A1 важнее, чем кажется.** В Chrome на машине разработчика `Default` занимает 1.58 ГБ, из них кэш — 921 МБ. Ещё 4.07 ГБ лежит в `OptGuideOnDeviceModel`, 188 МБ — в component/extension crx cache. Это не «кэш страниц», а компоненты браузера. Их нельзя чистить в Easy, но нельзя и игнорировать: это отдельный слой C.

**Почему A5/A6 с возрастом.** Удаление свежего файла из `%TEMP%` — классическая причина «установщик сломался». Фильтр «старше 24 часов» убирает 95 % мусора и почти весь риск. Для логов — 30 дней.

**Почему A7 безопасно, но не всегда полезно.** Дампы и WER не нужны обычному пользователю, но нужны при разборе падений. Поэтому цель остаётся в Easy, но с подписью «старые отчёты о падениях; после удаления нельзя разобрать причину».

### 4.2. Слой B — системное обслуживание

| ID | Цель | Пути / механизм | Обоснование | Риск и восстановление | Пресет |
|---|---|---|---|---|---|
| B1 | Компонентное хранилище | `DISM /Online /Cleanup-Image /StartComponentCleanup` | Штатный способ уменьшить WinSxS; ручное удаление запрещено; может освободить несколько ГБ | Долго; прерванная операция может оставить следы; повторяемо | Review (admin) |
| B2 | `Windows.old`, `$WINDOWS.~BT`, `$WinREAgent`, `ESD` | `cleanmgr` с профилем «Previous installations» / Storage Sense; если недоступно — только показ | После обновления Windows это десятки ГБ; текущая версия не видит | Необратимо: нельзя откатиться к прошлой версии Windows | Review (admin) |
| B3 | Кэш Windows Update | `SoftwareDistribution\Download`: стоп `wuauserv`, `bits`, `dosvc`; удаление содержимого; запуск в `finally`; проверка прав | Скачанные обновления можно скачать заново; 818 МБ на машине | Безопасно при корректном восстановлении служб; текущая версия не проверяет результат | Review (admin) |

| B6 | Старые точки восстановления | VSS: удалить все, кроме самой новой; показать даты и размер | Могут занимать десятки ГБ; текущая версия не видит | Необратимо; оставляем одну точку | Review (admin) |

**Почему B1 только через DISM.** WinSxS состоит из hardlink’ов. `get_dir_size` покажет десятки гигабайт, но реальное место может быть в разы меньше. Ручное удаление ломает обновления. `StartComponentCleanup` — единственный поддерживаемый путь. `/ResetBase` не включаем в обычный сценарий: после него нельзя удалить установленные обновления.

**Почему B2 нельзя делать через `rmdir`.** `Windows.old` защищён ACL и TrustedInstaller. Правильный путь — Disk Cleanup / Storage Sense. Если программный профиль `cleanmgr` не сработает, цель остаётся «только показ» — это лучше, чем «вроде удалили».

**Почему B3/B4 требуют admin и проверки.** Остановка `wuauserv` без прав молча не сработает, а `Remove-Item -ErrorAction SilentlyContinue` вернёт «OK». Нужно: проверить `is_admin()`, остановить службы, проверить `Status`, удалить, запустить, проверить, что службы снова `Running`. Если что-то не так — `ERR` с кодом, а не «Кэш WU очищен».

**Почему C1/C2/C5 — не Easy.** Пользователь не ожидает, что «очистка кэша» удалит 4 ГБ модели или среду разработки. Это допустимо только как отдельное решение с ценой восстановления. В UI у цели должно быть: «Будет удалено: 4.07 ГБ. Повторная загрузка: ~4 ГБ трафика. Команда: …».

**Почему `.antigravity/extensions` убирается.** Это не кэш, а каталог установленных расширений (аналог `~/.vscode/extensions`). Удаление ломает окружение и не восстанавливается автоматически. Если нужна очистка расширений — это отдельный сценарий «управление расширениями», а не очистка диска.

**Почему Telegram `tdata` сужается.** `tdata` содержит ключи, настройки и сессии, а не только медиа-кэш. Безопасная цель — только подпапки кэша внутри `tdata\user_data` (например, `cache`, `media_cache`, если они есть в конкретной версии). Остальное не трогаем. Если приложение запущено — предупреждаем, что часть файлов занята, и не убиваем процесс. Точный список подпапок фиксируется в тестах на реальной установке.

## 5. UX глубокой очистки

### 5.1. Место в приложении

Новый экран **«Глубокая очистка»** в sidebar (не замена «Очистке»):

- «Очистка» остаётся быстрым сценарием A + текущие цели;
- «Глубокая очистка» — пошаговый сценарий с планом и слоями.

Альтернатива: вкладка внутри «Очистки». Но экран уже насыщен, а глубокий сценарий требует отдельного пространства для плана и предупреждений. Поэтому отдельный экран.

### 5.2. Поток

1. **Сканирование.** Кнопка «Анализировать». Показывает карточки слоёв: «Безопасно», «Система», «Компоненты», «Остатки» с суммарным размером и числом целей. Системные карточки помечены замком, если нет прав.
2. **Выбор.** Ничего не выбрано. Кнопки: «Безопасный набор» (A, возраст, без занятых), «Снять», «Развернуть всё». У каждой цели — чекбокс, размер, бейдж риска, «почему» и «что потеряю».
3. **План.** Правая панель или отдельный шаг: итог по томам, топ-10 самых больших действий, список предупреждений («Chrome запущен — часть файлов будет пропущена», «Служба Windows Update будет остановлена и запущена», «Удаление `Windows.old` необратимо»). Кнопка «Показать все файлы» — виртуализированный список.
4. **Подтверждение.** Только после плана. Для необратимых целей — отдельный чекбокс «Я понимаю, что откат невозможен». Для моделей — «Будет скачано заново ~N ГБ».
5. **Права.** Если нужен admin — «Перезапустить с правами». План сохраняется; после перезапуска показывается тот же план и финальное подтверждение.
6. **Выполнение.** Прогресс: текущая цель, удалено байт, ошибки, кнопка «Стоп». Отмена — между чанками.
7. **Результат.** «Освобождено: X (подтверждено по тому)», «В корзину: Y», «Осталось: Z», «Ошибки: N» с топ-причинами. Кнопки: «Отчёт», «Открыть корзину», «Повторить безопасную очистку».
8. **История.** Каждая цель — отдельная строка с планом/фактом/томом/причиной ошибки. Экспорт CSV/JSON.

### 5.3. Тексты и состояния

- Заголовок: «Глубокая очистка»; подзаголовок: «Кэши, системный мусор и крупные файлы — с планом до удаления».
- Пустое состояние: «Нажмите “Анализировать”, чтобы увидеть, что можно освободить».
- Ошибка прав: «Для этой цели нужны права администратора. Безопасные цели можно очистить сейчас».
- Занятость: «Chrome запущен. Закройте его, чтобы очистить кэш полностью, или продолжите — занятые файлы будут пропущены».
- Модели: «Это модель, а не кэш. После удаления её нужно скачать заново».
- `Windows.old`: «После удаления нельзя вернуться к предыдущей версии Windows».

### 5.4. Доступность и MD3

- Все новые элементы — из `ui/components/md3.py`.
- Слои — `MDCard` с tonal-вариантами; риск — бейдж с цветовой ролью (`error`, `tertiary`, `primary`).
- Прогресс — существующий статус-бар + inline-прогресс на карточке.
- Никаких Tk-вызовов из воркеров: только `UiDispatcher`.
- Светлая/тёмная/system темы, 1024×660 — обязательная проверка скриншотами.

## 9. Риски и меры

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Ложное срабатывание auto-discover | средняя | потеря данных приложения | review-режим, порог, allowlist, только содержимое, корзина |
| Занятые файлы | высокая | частичная очистка | skip + отчёт, без kill |
| Служба не остановилась | средняя | «OK» при отказе | проверка статуса, `ERR`, `finally` |
| DISM долго/падает | средняя | зависание | таймаут, лог, отмена, без обещаний |
| `Windows.old` не удаляется | высокая | неверная цифра | fallback «только показ», не rmtree |
| Антивирус блокирует batch delete | средняя | отказ | fallback, понятная ошибка, подпись exe |
| Шум свободного места | высокая | неверный `freed` | две метрики + `confidence` |
| Пользователь не понимает модели | средняя | потеря трафика | отдельный слой, цена восстановления, ничего не выбрано |
| UAC-перезапуск теряет выбор | средняя | плохой UX | план в JSON + `--apply-plan` |
| Регрессия MD3 | низкая | визуальные дефекты | скриншоты, smoke |
