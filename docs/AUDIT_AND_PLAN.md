# DiskCleaner Pro v4 — аудит проекта, план развития и предложения

Дата аудита: 24.10.2026
Версия в коде: 4.6.0 (`pyproject.toml`, `__init__.py`)
Стек: Python 3.12+, CustomTkinter, ttk, SQLite, PowerShell/cmd, PyInstaller

---

## 1. Краткое резюме

Проект представляет собой Windows-утилиту для очистки диска в стиле CCleaner / BleachBit / WinDirStat:
9 экранов (Dashboard, Smart Clean, Analyzer, Disks, Duplicates, History, Startup, Uninstaller, Settings),
модульные очистители, история в SQLite, treemap, поиск дубликатов, управление автозагрузкой
и деинсталлятор с поиском остатков.

**Сильные стороны**

- Слоистая структура уже заложена: `models` / `services` / `cleaners` / `ui` — это правильная основа.
- Хорошее покрытие целей очистки (система, браузеры, dev tools, приложения, AI/ML, auto-discover).
- Есть уровни безопасности 🟢/🟡/🔴, безопасный режим, корзина, история, отчёты.
- UI на CustomTkinter выглядит современно, treemap с drill-down — сильная идея.

**Главные выводы**

1. **Текущая сборка неработоспособна для сканирования/очистки** в новом UI:
   `SmartCleanView` обращается к `self.root`, которого у `CTkFrame` не существует
   (проверено: у `tkinter.Frame`/`CTkFrame` есть только `_root`). Фоновый поток падает,
   кнопки остаются заблокированными.
2. Ряд настроек и обещаний из прошлого плана не реализован: «в корзину» игнорируется,
   переключатели настроек не читают конфиг, пользовательские правила нельзя удалить из UI,
   дубликаты нельзя удалять, у автозагрузки нет включения обратно.
3. Операции удаления в деинсталляторе и кастомных правилах **опасны**: удаление по подстроке
   имени, отсутствие предпросмотра, отсутствие защиты системных путей, повышение прав не запрашивается.
4. Отчётность врёт: `freed` берётся из размера до очистки, а отправка в корзину возвращает `True`
   даже при ошибке. Пользователь видит «освобождено N ГБ», которых на диске нет.
5. Нет тестов, CI, README, лицензии, `.gitignore`, логов падений, корректной сборки
   (`build-backend` в `pyproject.toml` невалиден). Репозиторий даже не инициализирован как git.

**Вердикт:** это хороший прототип с правильной архитектурой, но выпускать его как стабильный
релиз нельзя. Нужен короткий этап стабилизации (1–2 дня), затем этап безопасности и качества
(1–2 недели), и только после этого — развитие функций.

## 4. Критические дефекты (P0) — исправить до любого релиза

### P0-1. Сканирование и очистка падают (`self.root`)

Файл: `disk_cleaner_app/ui/views/smart_clean.py`, строки 153, 155–156, 162, 215, 222–223, 230.

```python
self.root.after(0, self._scan_done)   # AttributeError: 'SmartCleanView' has no attribute 'root'
```

`SmartCleanView` — это `CTkFrame` (наследник `tkinter.Frame`). У виджета есть только `_root()`
(метод) и `_root`-атрибут в CustomTkinter, но **нет** `root`. Ошибка возникает в фоновом потоке,
кнопки `Scan`/`Clean` остаются `disabled`, приложение выглядит «зависшим».

**Фикс:** использовать `self.after(0, ...)` (метод есть у любого виджета) и единый механизм
«воркер → `queue.Queue` → UI-поллер». Прямые вызовы Tk из потоков недопустимы.

### P0-2. `format_bytes` теряет дробную часть

Файл: `disk_cleaner_app/models/item.py`, строки 57–65.

```python
b //= 1024   # целочисленное деление
...
return f"{b:.1f} {unit}"
```

Проверено: `1_610_612_736` (1.5 ГиБ) → `"1.0 ГБ"`, `6_207_569_920` (5.8 ГиБ) → `"5.0 ГБ"`.
Все размеры в приложении занижаются, иногда на 40–50%.

**Фикс:** делить на `1024.0` и округлять только при выводе; добавить юнит-тест.

### P0-3. Настройка «Перемещать в корзину» ни на что не влияет

Файл: `ui/views/smart_clean.py`, строка 203: значение читается в `to_recycle`, но никуда
не передаётся. Очистители вызывают `safe_rmtree`/`safe_rm_contents` со своими значениями
по умолчанию, а системные (`system.py`) всегда передают `to_recycle=False`.

**Фикс:** передавать `CleanOptions(to_recycle, safe_mode, ...)` в `CleanEngine` → в каждый
`cleaner.clean(ctx)`; убрать хардкод из очистителей.

### P0-4. Отчёты о «освобождённом месте» недостоверны

- `services/cleaner.py:15` — `self.freed = cleaner.size` (размер **до** очистки), независимо от результата.
- `cleaners/base.py:142–156` — `_send_to_recycle()` возвращает `True` всегда, даже если PowerShell
  завершился с ошибкой или файл остался.
- `safe_rm_contents()` игнорирует ошибки `unlink` и всё равно возвращает `True`.

**Следствие:** история, дашборд и отчёт показывают несуществующие гигабайты; пользователь
теряет доверие к приложению.

**Фикс:** после очистки пересчитывать фактический размер (или использовать результат
`SHFileOperation`/`IFileOperation`), возвращать `CleanResult(ok, bytes_freed_actual, errors)`,
сверять `free space` до/после. Статус `OK` — только при подтверждённом удалении.

### P0-5. В Easy-режиме скрытые 🟡/🔴 элементы считаются выбранными

Файл: `ui/components/item_tree.py`, строки 116–120, 179–191.

```python
if iid not in self._checked:      # скрытые элементы сюда вообще не попадают
    ...
return [c for c in self._cleaners
        if self._checked.get(c.id, True) ...]   # отсутствующий id → True
```

Если пользователь выключил «Безопасный режим» и остался в Easy, скрытые CAUTION/ADVANCED
всё равно попадут в очистку. Это прямое нарушение ожиданий и потенциальная потеря данных.

**Фикс:** хранить явное состояние для всех целей (`checked = False` для скрытых), а также
строить `selected` только из элементов, реально отображённых в дереве.

### P0-6. Действия без размера невозможно выполнить

`get_selected()` фильтрует `c.size > 0`. Поэтому `DNSCacheCleaner` (size = 0) и любые
«сервисные» действия никогда не выполняются, даже если отмечены. Кроме того, при ошибке
сканирования размер становится `-1` и маскируется под «0 Б».

**Фикс:** отделить «объём к освобождению» от «действия»: `size: int | None`, `reclaimable: bool`,
`actionable: bool`. В таблице показывать «—» для действий.

### P0-7. Дублирование целей и двойной учёт

- `ChromeCacheCleaner` уже включает `Code Cache`, а `ChromeCodeCacheCleaner` считает его ещё раз.
- `discover.py` находит те же папки (`Cache`, `Code Cache`, `GPUCache`) и создаёт
  `auto_*`-цели с другими id.
- Дедупликация в `ScanEngine` идёт **по id**, а не по каноническому пути.

**Следствие:** завышенные размеры, двойная очистка, гонки за одни и те же файлы.

**Фикс:** реестр владения путями (`canonical_path → owner`), auto-discover исключает пути,
уже покрытые встроенными очистителями; убрать `chrome_code` или `Code Cache` из Chrome-мишени.

### P0-8. Деинсталлятор удаляет данные по подстроке без предпросмотра

Файл: `services/uninstaller.py`.

- `uninstall()` (89–134) запускает `uninstall_string` через `shell=True`, таймаут 60 с,
  **не проверяет успех**, после чего всё равно чистит реестр и папки.
- `_scan_registry()` (136–156) пытается удалять ключи `Software\<app_name>`, включая
  `HKCU\Software\Microsoft\...\Uninstall\<app_name>`.
- `_scan_appdata()` (158–179) удаляет **любой** каталог в Local/Roaming/LocalLow/ProgramData,
  в имени которого встречается имя приложения (например, «Code» → чужие папки).
- `_scan_full_disk()` (181–212) обходит `C:\Program Files`, `C:\Program Files (x86)`, домашний
  каталог и удаляет папки по совпадению всех слов имени, **прямо во время обхода**, без списка
  и подтверждения; `break` обрывает обход остальных каталогов.
- Нет проверки, что путь не является системным; нет elevated-режима; нет отката.

**Фикс:** удаление остатков только как **предпросмотр с чекбоксами** (по умолчанию ничего
не выбрано), строгий `PathGuard`, удаление в корзину, запуск деинсталлятора с ожиданием
процесса и проверкой кода возврата, отдельный elevated helper. Автоматический deep scan
по подстроке — убрать.

### P0-9. «Отключение» автозагрузки необратимо и не проверяет результат

Файл: `services/startup.py`.

- `disable_item()` для HKCU/HKLM делает `reg delete /v <name> /f` — значение исчезает навсегда,
  бэкапа нет; `enable_item()` для реестра не реализован (только для папки Startup).
- `add_item()` и `disable_item()` возвращают `True` независимо от `returncode`.
- Парсинг `reg query` завязан на ровно четыре пробела и формат `REG_SZ`, ломается на
  `REG_EXPAND_SZ`/локализованной Windows; дедупликация по имени теряет записи HKLM.
- Не читаются `StartupApproved`, задачи планировщика, службы.

**Фикс:** хранить отключённые значения в отдельной ветке (`...\Run-disabled`) или в JSON-бэкапе,
показывать состояние toggle, проверять `returncode`, использовать `winreg` вместо парсинга текста,
добавить `StartupApproved` и `schtasks`.

### P0-10. Пользовательские правила не защищены

- `ConfigManager.add_custom_rule()` принимает любой путь, включая `C:\Windows`, `C:\Users`,
  корень диска; `CustomRuleCleaner.clean()` удаляет папку **целиком**.
- `safe_rm_contents()` использует `child.is_dir()` (следует junction/symlink), т.е. может
  рекурсивно очистить содержимое связанного каталога за пределами целевой папки.
- `custom_rule` игнорирует `to_recycle`; id получается двойным (`custom_custom_<ts>`).

**Фикс:** `PathGuard` (запрет корней, системных каталогов, домашних Documents/Desktop/Downloads,
путей вне белого списка), `os.path.isjunction`/`lstat` при обходе, подтверждение для 🔴,
корзина по умолчанию, нормальные UUID-id.

### P0-11. Системные операции требуют прав администратора, но приложение их не запрашивает

Очистка `C:\Windows\Temp`, `Prefetch`, `SoftwareDistribution\Download`, `FontCache`,
`Minidump`, части `ProgramData` невозможна без elevation. Все эти очистители возвращают `OK`
и рисуют «освобождено», даже когда доступ запрещён. В `DiskCleaner.spec` нет `uac_admin=True`,
нет и elevated helper'а.

**Фикс:** как минимум — манифест `requireAdministrator`; лучше — обычный запуск + отдельный
процесс-помощник, который поднимает права только для конкретной операции и возвращает JSON-результат.

### P0-12. После очистки и добавления правила состояние UI ломается

- `smart_clean.py:249` после очистки перезаполняет дерево **старыми** размерами; повторного
  сканирования нет, «Выбрано: N ГБ» остаётся прежним.
- `_add_custom_rule()` (311–338) обнуляет `self._all_cleaners` и запускает скан: встроенные
  очистители исчезают из списка до следующего `_load_cleaners()`.
- `load_cleaners()` вызывается только при переходе на вкладку/хоткее.

**Фикс:** после очистки — инкрементальный re-scan очищенных целей; добавление правила —
`registry.reload()` без потери списка; единый `AppState` с событиями.

## 5. Важные проблемы (P1)

### 5.1. Темы и визуал

- `ThemeManager.colors` (`ui/theme.py:31–34`): для `"system"` всегда возвращает `LightColors`,
  даже если ОС в тёмном режиме → светлые карточки на тёмных виджетах и наоборот.
- `refresh_theme()` реализован частично: `settings.py` — `pass`, `item_tree.py` — `pass`,
  `startup.py` — `pass`; в `header.py`, `statusbar.py`, `dashboard.py` обновляются не все дети.
- Жёстко зашитые цвета: `disk_gauge.py` (`#2a2a50`, `#f0f0ff`, `#9090b0`), текст treemap
  (`#0c0c18`), `analyzer`/`duplicates` текстовые блоки; в светлой теме читаемость ломается.
- `DiskGauge.update()` перекрывает стандартный `tk.Canvas.update()` — риск для внутренних
  вызовов Tk; переименовать в `set_values()`.
- Нет tooltip'ов в сайдбаре (пустой `bind`), нет подписей к иконкам — навигация неочевидна.
- Treemap не перерисовывается при изменении размера окна; нет cushion-эффекта и цветов
  по расширениям (обещано в старом плане).

### 5.2. Потоки и производительность

- Вызовы Tk (`after`) из рабочих потоков в `smart_clean` (кроме отсутствующего `root`) —
  сами по себе небезопасны; нужен `queue.Queue`.
- `ScanEngine` держит `ThreadPoolExecutor` без `shutdown()`; потоки не daemon → возможное
  зависание при выходе.
- `auto_discover_items()` выполняется **до** запуска futures (`scanner.py:27–33`), рекурсивно
  обходит AppData и считает размеры — прогресс-бар стоит минутами.
- Нет отмены сканирования/очистки/анализа; кнопки только блокируются.
- `get_dir_size` и треемap/анализатор делают полный рекурсивный обход `C:\` — на HDD это
  десятки минут; нет исключений, кэша, параллельности, прогресса.
- `safe_rm_contents` вызывает PowerShell **на каждый файл** для корзины: удаление тысяч
  файлов занимает минуты. Нужен один пакетный `SHFileOperationW` с `FOF_ALLOWUNDO`.
- `RecycleBinCleaner.get_size()` и `Prefetch`/`WU` запускают внешние процессы на каждое
  сканирование — 4 воркера × PowerShell = тяжёлая нагрузка.
- Кэш auto-discover (TTL 5 мин) отдаёт те же **инстансы** очистителей — состояние размера
  разделяется между вызовами; лучше кэшировать пути, а не объекты.

### 5.3. Настройки и история

- `SettingsView` не получает геттер конфига: `recycle_var`/`safe_var` всегда `True` при
  открытии, `theme_var` — `"dark"` по умолчанию; переключение перезаписывает реальные
  настройки. `refresh()` не синхронизирует переключатели.
- Нет UI для добавления/удаления пользовательских правил (`remove_custom_rule` нигде не вызывается).
- `history.details` не заполняется; нет фильтра/экспорта; счётчик «Очисток» = числу записей,
  а не числу целей.

### 5.5. Качество кода и мёртвый код

- Легаси-модули (`core.py`, `gui.py`, `cleaners.py`, `scanners.py`, `analyzer.py`) не используются,
  но собираются; дублируют конфиг, историю, удаление, format_bytes — риск «двух правд».
- Мёртвые API: `BaseCleaner.to_item()`, `BaseCleaner.preview()`, `CleanerRegistry.get_safe()`,
  `ScanEngine.shutdown()`, `remove_empty_folders()`, `_make_placeholder()`, `CleanupItem`.
- Эмодзи как ключи данных (`SafetyLevel.SAFE = "🟢"`, `GROUP_*`) — хрупко, мешает локализации
  и сортировке; порядок групп продублирован в `item_tree.py`.
- Широкие `except Exception: pass` в 20+ местах — ошибки не диагностируются.
- Нет `logging`, нет обработчика необработанных исключений, нет файла лога, нет single-instance.
- `__main__.py` выполняет `main()` при импорте (нет `if __name__ == "__main__"`).
- Импорты: неиспользуемые (`to_recycle`, `auto_discover_items`, `remove_empty_folders`,
  `SIDEBAR_WIDTH`, `FONT_BOLD` и др.) — нужен линтер.

**Модель потока:** UI → `EventBus` → сервис → `queue.Queue` → UI-поллер (`after(50)`).
Ни один рабочий поток не вызывает Tk напрямую. Любая длинная операция принимает
`threading.Event` для отмены.

**Модель безопасности:**

```
TargetSpec → PathGuard.validate() → CleanPlan (dry-run, объём, риски)
           → подтверждение (🟢 без диалога, 🟡 диалог, 🔴 ввод/явная галочка)
           → CleanEngine (recycle / elevation) → verify → history + audit log
```

## 8. Продуктовые предложения (backlog)

### Очистка
- Пакетная корзина через `SHFileOperation` (скорость ×10–100).
- Закрытие/предупреждение о запущенных браузерах и приложениях перед очисткой кэша.
- Все профили браузеров (`Default`, `Profile 1..N`), а не только `Default`.
- `cleanmgr /sagerun` для Windows Update / Windows.old (вместо ручного удаления).
- Новые безопасные цели: `%LOCALAPPDATA%\CrashDumps`, DirectX/NVIDIA shader cache,
  `CBS`/`DISM` логи, `Teams`/`VS Code` кэш, `Windows.old`, `Delivery Optimization`.
- Убрать/перевести в 🔴 рискованные цели: Telegram `tdata`, Prefetch, убийство `explorer.exe`
  ради эскизов. Для Telegram чистить только явно кэш-каталоги, не `tdata` целиком.
- Оценка «что будет, если удалить» — сколько места реально освободится и что перестанет работать.

### Анализ
- Выбор диска (пользователь уже держит `scan_d.ps1` для D: — сейчас приложение смотрит только C:).
- Кэш обхода и инкрементальное сканирование; исключения `$Recycle.Bin`, `System Volume Information`.
- Таблица вместо текста: сортировка, открыть в проводнике, «в корзину».
- Treemap: resize, hover-tooltip, хлебные крошки, цвета по типу файла.

### Дубликаты
- Трёхфазный поиск (размер → 64 КБ → полный хэш), BLAKE2b вместо MD5.
- Hardlink/symlink-детект, исключение системных папок, минимальный размер и маски.
- Групповой предпросмотр, авто-выбор «оставить один», удаление в корзину, отмена.

### Автозагрузка
- Toggle, `StartupApproved`, задачи планировщика, службы, бэкап и восстановление,
  «влияние на загрузку» (как в Task Manager), открыть расположение.

### Деинсталлятор
- Только официальный деинсталлятор + проверка, что программа исчезла.
- Остатки — отдельный предпросмотр с чекбоксами и уровнями; никакого auto-delete.
- Поддержка MSI/Store-приложений (`Get-AppxPackage`), установка даты/размера, сортировка.

### Платформа
- Планировщик очистки (раз в неделю/при <10% свободного места).
- Tray-режим и уведомления.
- Тёмная/светлая иконка, DPI, локализация RU/EN.
- Экспорт/импорт настроек и правил, портативный режим (данные рядом с exe).
- Проверка обновлений и канал бета-версий.
